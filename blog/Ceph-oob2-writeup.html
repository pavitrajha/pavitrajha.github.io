Linux libceph: OOB Read in decode_watchers() (CVE-2026-80557)

Linux Kernel libceph Client | net/ceph/osd_client.c | Slab Memory Safety | Vulnerability Write-up

1. Summary

CVE-2026-80557 is an out-of-bounds read vulnerability in the Linux kernel's libceph client within decode_watchers() in net/ceph/osd_client.c.

The function used a bare ceph_decode_32() operation immediately after ceph_start_decoding(), without verifying that four bytes remained in the received OSD reply buffer.

The root cause is that ceph_start_decoding() accepts struct_len=0 as valid. The internal ceph_decode_need(p, end, 0, bad) check succeeds because zero bytes are required. This can leave the decoding cursor positioned exactly at end.

The immediately following ceph_decode_32(p) then reads four bytes past the validated buffer boundary. The resulting value is assigned to *num_watchers and passed into kzalloc_objs() as the watcher allocation count.

2. Vulnerability Execution Path

The vulnerable parser processes replies associated with CEPH_OSD_OP_LIST_WATCHERS:

  |     |

A malicious or compromised OSD can provide an obj_list_watch_response_t reply with struct_len=0. The structure header is accepted, but the parser immediately attempts to decode a four-byte watcher count from a position where no bytes remain.

3. Vulnerability Description & Mechanics

The vulnerable decoding sequence is: 

ceph_start_decoding(p, end, 1, "obj_list_watch_response_t",
                    &struct_v, &struct_len);

*num_watchers = ceph_decode_32(p);

Successful validation of the structure header does not guarantee that subsequent fields remain available. 

struct_len = 0
|
v
ceph_start_decoding() succeeds
|
v
p == end
|
v
ceph_decode_32(p)
|
X
|
4-byte out-of-bounds read

The value read from beyond the receive buffer is subsequently used as the watcher count: 

*watchers = kzalloc_objs(**watchers, *num_watchers, GFP_NOIO);

This makes the unchecked decode security-relevant beyond the memory access itself: memory outside the validated message can influence a subsequent allocation-count decision.

4. Source Code Analysis

The vulnerable code was: 

if (ret)
        return ret;

*num_watchers = ceph_decode_32(p);

*watchers = kzalloc_objs(**watchers, *num_watchers, GFP_NOIO);
if (!*watchers)
return -ENOMEM;

No boundary check occurs between the successful return from ceph_start_decoding() and the four-byte decode.

The sibling decode_watcher() function already used the bounds-aware decoding pattern: 

ceph_decode_copy_safe(p, end, ...);
ceph_decode_64_safe(p, end, ...);
ceph_decode_skip_32(p, end, ...);

The fix brings decode_watchers() in line with this established pattern. 

ceph_decode_32_safe(p, end, *num_watchers, bad);

6. Threat Model & Impact Assessment

  • Primary Primitive: Four-byte slab out-of-bounds read.
  • Data Flow: The value obtained from out-of-bounds memory is passed into the watcher allocation-count path.
  • Attack Vector: A malicious or compromised OSD provides a malformed obj_list_watch_response_t reply.
  • Reachable Operation: CEPH_OSD_OP_LIST_WATCHERS.
  • Privilege Model: Under the stated attacker model, no additional privilege is required after the attacker can establish or control the relevant OSD session.

The KASAN reproduction directly establishes the out-of-bounds read and its propagation into the watcher-count path. Further consequences can depend on allocator state and surrounding kernel execution context, so this analysis does not claim exploitation capabilities beyond the demonstrated primitive.

ceph_decode_32_safe() verifies that four bytes remain before performing the decode. A malformed reply leaving p == end is therefore rejected with -EINVAL.

8. Affected Configurations

  • Threat Model: Kernel clients receiving replies from a malicious or compromised OSD.

9. Upstream Patch & Timeline

CVE-2026-80557 was assigned to the out-of-bounds read condition in decode_watchers().

The upstream fix commit is: 

00ead17c7de137a692edee59f2772e6af687e8eb

The vulnerable functionality was introduced by: 

a4ed38d7a180 ("libceph: support for CEPH_OSD_OP_LIST_WATCHERS")

The patch was submitted with Cc: stable@vger.kernel.org and was applied upstream. The final revision incorporated review feedback and used the existing safe decode pattern already present in related libceph parsers.

The final fix is conceptually small but restores an important parser invariant: every fixed-width field must independently establish that its bytes remain available before decoding.
